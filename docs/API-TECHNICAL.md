# Beauty Twin API：商赛展示版

## 一句话说明

Beauty Twin 通过统一的 `/api` 接口，把用户图片、产品信息和肤况输入交给 AI 与云服务处理，再返回可直接展示在小程序中的护理建议、妆容方案和产品信息。

## 1. 我们主要用了哪些接口？

| 功能 | 接口 | 给用户带来的结果 |
|---|---|---|
| AI 护肤计划 | `POST /api/home/generate-plan` | 根据肤况、时间和已有产品，生成早晚护理步骤 |
| 成分安全检查 | `POST /api/compatibility/check` | 判断产品能否一起使用，并提示风险 |
| 包装识别 | `POST /api/ocr/recognize` | 从产品包装图片中识别品牌、品名和成分 |
| 商品识别 | `POST /api/product/recognize` | 一张照片识别多个美妆产品 |
| 条码识别 | `POST /api/barcode/recognize` | 扫描二维码或条形码，获取产品信息 |
| AI 妆容生成 | `POST /api/makeup/generate` | 根据场景和风格生成妆容方案与步骤 |
| 妆教解析 | `POST /api/makeup/parse-tutorial` | 把妆教内容拆成容易跟练的步骤 |
| 头像/妆效生成 | `POST /api/avatar/generate`、`POST /api/makeup/render` | 生成个性化头像或妆效预览 |
| 产品管理 | `GET/POST /api/products` | 保存和读取用户的化妆台产品 |
| 回收与积分 | `GET/POST /api/recycling` | 记录空瓶回收并累计环保积分 |

## 2. 接口怎么工作？

```text
用户输入
  ↓
图片 / 肤况 / 产品 / 使用场景
  ↓
Beauty Twin API
  ↓
AI + 云服务分析
  ↓
护理计划 / 妆容步骤 / 产品信息 / 风险提醒
```

所有接口都使用 JSON；图片可以直接用 Base64 上传。接口成功时返回 `success: true` 和结果数据，失败时返回错误信息。

## 3. 背后的 AI 和云服务

| 平台 | 主要用途 |
|---|---|
| 腾讯云 | OCR、二维码/条形码识别、商品识别 |
| 豆包/火山方舟 | 图片理解、商品识别、结构化信息提取 |
| Gemini / DeepSeek | 护理计划、妆容方案、成分分析和文本生成 |
| Cloudflare D1 / R2 | 保存产品、计划、回收记录和图片 |
| 腾讯 WebAR | 静态图片试妆和妆效预览 |

## 4. 一个典型用户流程

1. 用户拍摄化妆品包装图。
2. `/api/ocr/recognize` 识别产品信息。
3. 产品保存到 `/api/products`，形成个人化妆台。
4. 用户输入肤况和可用时间。
5. `/api/home/generate-plan` 生成专属护理计划。
6. `/api/compatibility/check` 检查产品搭配是否安全。
7. 用户根据返回的步骤完成护理或妆容。

## 5. 商赛 PPT 可直接使用的总结

> 我们没有把 AI 能力分散在页面里，而是通过统一 API 层连接图片识别、成分分析、护理规划和虚拟试妆。这样，用户只需拍照并补充简单需求，系统就能把“识别产品—理解肤况—给出建议—辅助执行”串成一条完整链路。

## 6. 技术特点

- **统一入口**：前端只调用 `/api`，便于后续替换 AI 服务。
- **多模型协作**：识别、分析、生成分别使用更适合的服务。
- **自动降级**：某个 AI 服务不可用时，系统会尝试备用服务或演示数据。
- **服务端保密**：API Key 只放在服务端，前端不暴露密钥。
- **可扩展**：产品、护理计划、回收积分等数据可接入 Cloudflare 数据库。
